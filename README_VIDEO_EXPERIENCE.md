## Registration, security, and email

- `/video-experience`: minimal form, first name and email required, optional marketing checkbox (unchecked by default), UTM source capture.
- `/video-experience/watch?ticket=...`: emailed confirmation link. AES-256-GCM authenticated, non-guessable, 14-day expiration.
- List `KSAI Video Experience: Verified Access` is created and updated only after the user opens a verified email link.
- List `KSAI Video Experience: Optional Updates` is used only when a person explicitly checks the optional consent box.
- Both lists deliberately remain separate from **Webinar: All registrants** and **Webinar: Nurture (confirmed)**, which are reserved for live webinar signups.
- Link email is transactional via the website's existing Brevo transport. Never add people to a marketing list just to obtain access.
- Environment variables: `BREVO_API_KEY`, `VIDEO_ACCESS_SECRET` (random 32+ character high-entropy value), and optional `VIDEO_EXPERIENCE_VIDEO_URL` (HTTPS playback URL after final media is hosted).
- Video file is not stored in GitHub. Note: a public video URL remains shareable even with a gated watch page. For genuinely private media, use expiring playback URLs generated by a trusted media host and verify tickets on the server.
- The basic in-memory request throttle is NOT a production anti-abuse solution across replicas/restarts. Add durable per-IP and per-email rate limiting, a CAPTCHA, and monitoring before broad paid traffic.
- Redemption records viewer attribution but does not yet track playback completion.
- The emailed link itself contains no plaintext address; the encrypted ticket can still be forwarded, so it is a possession-link, not account authentication.
